\chapter{สรุป}\label{ch:concl}

\section{สรุปผลตามวัตถุประสงค์}\label{sec:concl-objectives}

\begin{enumerate}[leftmargin=1.6em]

\item \textbf{โมเดลกราฟการโจมตี (สำเร็จ)} node แบบ \texttt{(resource, privilege)} และ
edge สามชนิดพร้อม \texttt{domain} กำกับ (หัวข้อ~\ref{sec:design-model}) ใช้ได้ทั้งกราฟจำลอง 216 โครงสร้าง
และกราฟจาก lab จริงโดยไม่ต้องแก้โค้ดวิเคราะห์เลย (หัวข้อ~\ref{sec:impl-analyzer},~\ref{sec:eval-lab}) ความถูกต้องของ
โครงสร้างถูกตรวจด้วย brute force บนกราฟสุ่ม 300 กราฟ (หัวข้อ~\ref{sec:impl-tests})

\item \textbf{$p(e)$ ที่อธิบายที่มาได้ (สำเร็จบางส่วน)} ทุก edge มี \texttt{p\_source} และ
\texttt{p\_input} กำกับจริง ฟังก์ชัน fit จาก CVSS ไปเป็น EPSS ใช้งานได้และตรวจสอบ
ย้อนกลับได้ทีละ metric (หัวข้อ~\ref{sec:eval-pe}) แต่ความแม่นยำมีจำกัด: $R^2$ ในสเกล logit เท่ากับ
0.219 เท่านั้น และคลาดเคลื่อนมากที่สุดบน edge ที่มีโอกาสถูกโจมตีสูง (top-decile $|r|$
1.938 nats เทียบ pooled 0.587) ซึ่งเป็นกลุ่มที่ตัดสินอันดับเส้นทางจริง ข้อจำกัดนี้ถูก
รายงานตรงไปตรงมา ไม่ปกปิด ตามที่ประกาศไว้ในหลักการของโครงงาน

\item \textbf{เทียบ dominator tree กับ weighted min-cut (สำเร็จ)} ทั้งสองวิธีคำนวณบน
กราฟชุดเดียวกันด้วยหน่วยที่เทียบกันได้ (node-splitting, หัวข้อ~\ref{sec:design-mincut}) พบว่าเมื่อใช้น้ำหนัก
EPSS จริง min-cut ให้คำตอบตรงกับ dominator set เพียง 72\% ของกรณีที่เทียบได้ ต่างจาก
เมื่อใช้น้ำหนัก CVSS หรือ uniform ที่ตรงกัน 100\% (หัวข้อ~\ref{sec:eval-cut-agree}) นี่คือข้อค้นพบหลักของ
วัตถุประสงค์ข้อนี้: วิธีเชิงโครงสร้างกับวิธีที่ใช้ข้อมูลเชิงประจักษ์จริงให้คำตอบต่างกันได้จริง
ไม่ใช่แค่ในทางทฤษฎี

\item \textbf{วัดความทนทานของอันดับ (สำเร็จ)} พบว่าน้ำหนักที่คลาดเคลื่อนไม่ทำให้อันดับ
พัง แม้ขยายสัญญาณรบกวนไปถึง 8 เท่าของค่าที่วัดได้จริง (Jaccard@5 ยังอยู่ที่ 0.912,
หัวข้อ~\ref{sec:eval-noise}) แต่ edge ที่ขาดหายกระทบรุนแรงกว่ามาก (Jaccard@5 เหลือ 0.493 เมื่อลบเพียง
5\%, หัวข้อ~\ref{sec:eval-drop}) ส่วนคำถามว่า EPSS ช่วยได้มากกว่า CVSS หรือไม่ คำตอบคือไม่มี
หลักฐานเพียงพอ เพราะกราฟจำลองไม่มีค่าจริงให้เทียบ (EPSS เทียบ CVSS ให้ Jaccard@5
0.951 ใกล้เคียงกับ EPSS เทียบน้ำหนักสุ่มล้วนที่ 0.924 มาก, หัวข้อ~\ref{sec:eval-models})

\item \textbf{lab จริงสองฝั่ง (สำเร็จบางส่วน)} pipeline เดียวกันใช้ได้กับกราฟจาก
Terraform/LocalStack/Cartography/Neo4j จริง (หัวข้อ~\ref{sec:eval-lab}) แต่ไม่ครบตามที่เสนอไว้ทุก
ส่วน: ใช้ Docker network แทน GNS3, ใช้ \texttt{nmap} แทน Nessus (จึงไม่มี edge ชนิด
CVE ในกราฟ lab เลย) และใช้ LocalStack แทน AWS จริง เพราะบัญชี AWS Academy
Learner Lab บล็อกการสร้าง IAM resource ทั้งหมด การตัดสินใจทดแทนแต่ละจุดมีเหตุผล
ที่บันทึกไว้ ไม่ใช่การข้ามแบบเงียบ ๆ (ภาคผนวก~\ref{app:deviation})

\end{enumerate}

โดยรวม วัตถุประสงค์ข้อ 1, 3 และ 4 สำเร็จครบตามที่ตั้งไว้ ข้อ 2 และ 5 สำเร็จบางส่วน
ด้วยข้อจำกัดที่ระบุไว้ชัดเจนและมีเหตุผลรองรับทุกจุด

\section{ข้อจำกัด}\label{sec:concl-limits}

ข้อจำกัดของโครงงานนี้สรุปไว้ครบถ้วนแล้วในหัวข้อ~\ref{sec:eval-limits} (ท้ายบทที่~\ref{ch:eval}) ซึ่งครอบคลุมทั้ง
ขอบเขตของโมเดล (ไม่มี AND-node), ข้อจำกัดของ lab (ไม่มี edge ชนิด CVE, ไม่ผ่าน
Cartography ฝั่ง on-prem, ใช้ LocalStack แทน AWS จริง), ข้อจำกัดของ rubric (3 กลุ่มคลาส
มีค่า $p$ เท่ากันเป๊ะเพราะตกอยู่ใน CVSS cell เดียวกัน) และข้อจำกัดของตัวสร้างกราฟ
จำลอง (โครงสร้างแบบโซ่ ยังไม่ได้ตรวจกับ topology จริง)

\section{แนวทางพัฒนาต่อ}\label{sec:concl-future}

\begin{itemize}[leftmargin=1.6em]
\item \textbf{ทดสอบกับ AWS จริง} เมื่อมีบัญชีที่ไม่ใช่ AWS Academy Learner Lab เพื่อยืนยัน
ว่าผลจาก lab ไม่ได้ขึ้นกับข้อจำกัดเฉพาะของ LocalStack
\item \textbf{ใช้ Nessus หรือ OpenVAS ที่ใช้งานได้จริง} เพื่อให้กราฟ lab มี edge ชนิด CVE
อย่างน้อยหนึ่งเส้น และทดสอบฝั่ง EPSS ของวัตถุประสงค์ข้อ 2 บนระบบจริงได้
\item \textbf{เขียนตัวเก็บข้อมูลฝั่ง on-prem ที่ผ่าน graph database} แทนการอ่านตรงจาก
\texttt{docker exec}/\texttt{nmap} เพื่อให้ pipeline ทั้งสองฝั่งสมมาตรกัน
\item \textbf{รองรับ AND-node บางส่วน} สำหรับกรณีที่พบบ่อยในโลกจริง เช่นการโจมตีที่
ต้องมีทั้งช่องโหว่ซอฟต์แวร์และการตั้งค่าผิดพร้อมกัน โดยไม่ต้องรองรับเต็มรูปแบบแบบ MulVAL
\item \textbf{วัดสัดส่วนเส้นทางข้ามโดเมนด้วย k เส้นทางแทนเส้นทางเดียว} (k-shortest path)
เพื่อตอบคำถาม ``สัดส่วนของเส้นทางอันตราย'' ได้ครบถ้วนกว่าการดูเฉพาะเส้นทางถูกสุด
เพียงเส้นเดียวตามที่ทำในหัวข้อ~\ref{sec:eval-cross}
\item \textbf{ตรวจสอบตัวสร้างกราฟจำลองกับ topology เครือข่ายจริง} เพื่อยืนยันว่าโครงสร้าง
แบบโซ่ที่พบ (หัวข้อ~\ref{sec:eval-threats}) เป็นคุณสมบัติของเครือข่ายไฮบริดจริงด้วยหรือเป็นเพียงลักษณะ
เฉพาะของตัวสร้างกราฟ
\end{itemize}
