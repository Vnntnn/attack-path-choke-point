\chapter{บทนำ}

\section{ที่มาและความสำคัญของปัญหา}\label{sec:intro-background}

องค์กรทุกวันนี้ส่วนใหญ่ไม่ได้มีเพียงเครือข่ายภายใน (on-premise) อย่างเดียวอีกต่อไป
แต่ผสมกับระบบบนคลาวด์ (cloud) จนกลายเป็นโครงสร้างพื้นฐานแบบ Hybrid
ผู้โจมตีที่ยึดเครื่องแรกได้มักไม่หยุดอยู่แค่นั้น แต่เดินทางต่อไปเรื่อย ๆ จนถึงข้อมูลสำคัญ
เครื่องมือกลุ่ม Attack Path Management เช่น BloodHound, Wiz และ XM Cyber ช่วยแก้
ปัญหานี้ได้ในระดับหนึ่ง ด้วยการมองทั้งระบบเป็นกราฟ แล้วหาเส้นทางที่ผู้โจมตีเดินได้
แต่เครื่องมือเหล่านี้ยังเหลือช่องว่างสำคัญสองจุด

ช่องว่างแรกคือการให้น้ำหนักแต่ละเส้นทาง เครื่องมือเชิงพาณิชย์จัดอันดับได้ว่าเส้นทางใด
อันตรายที่สุด แต่คะแนนที่ใช้มักอธิบายที่มาไม่ได้ และไม่เคยมีรายงานว่าหากข้อมูลที่ใช้
คำนวณคลาดเคลื่อนไปสัก 20--30\% (ซึ่งเป็นเรื่องปกติของข้อมูลช่องโหว่ในโลกจริง) อันดับ
ที่ได้จะยังเชื่อถือได้หรือไม่ ช่องว่างนี้ชัดเจนที่สุดบน edge ที่ข้ามโดเมน: เครื่องมือฝั่ง
network (RedSeal, Skybox) กับฝั่ง cloud (Wiz) เป็นคนละตัวกัน edge ที่ข้ามระหว่าง
สองฝั่งจึงกลายเป็นจุดบอดร่วมของทั้งคู่ เช่น ไฟล์ \texttt{\~{}/.aws/credentials} ที่ตกค้าง
บนเซิร์ฟเวอร์ในองค์กร หรือการใช้ SSRF ดึง token ออกจาก IMDS ทั้งที่การโจมตีจริงมัก
เดินผ่านทางเหล่านี้

ช่องว่างที่สองคือการวิเคราะห์จุดตัด (choke point) ของกราฟข้ามโดเมนยังไม่เป็นระบบ:
แนวคิด attack graph มีมาตั้งแต่ Sheyner ในปี 2002 และ MulVAL ในปี 2005 ส่วนการหา
จุดตัดด้วย dominator tree และด้วยน้ำหนักเชิงความน่าจะเป็นต่างก็เป็นวิธีที่รู้จักกันดี
แต่ยังไม่มีงานที่นำทั้งสองวิธีมาเทียบกันโดยตรงบนกราฟที่รวมทั้งสองโดเมน พร้อมวัดว่า
ผลลัพธ์ที่ได้น่าเชื่อถือเพียงใด โครงงานนี้จึงเติมช่องว่างทั้งสองข้อ: ให้วิธีกำหนดน้ำหนัก
ที่อธิบายที่มาได้ (รายละเอียดในบทที่~\ref{ch:studied}) และวัดความน่าเชื่อถือของอันดับจุดตัดที่ได้อย่าง
เป็นระบบ (ผลการทดลองในบทที่~\ref{ch:eval})

\section{ปัญหาที่ต้องการแก้ไข}\label{sec:intro-problem}

สรุปจากที่มาข้างต้น ปัญหาหลักที่โครงงานนี้ตั้งใจแก้มีสองข้อ ข้อแรกคือ \textbf{น้ำหนักบน
edge ของ attack graph ขาดความน่าเชื่อถือ} เครื่องมือเชิงพาณิชย์ให้คะแนนความอันตราย
ของแต่ละเส้นทางได้ แต่ไม่เปิดเผยว่าคะแนนนั้นมาจากอะไร และไม่เคยรายงานว่าหากข้อมูล
ที่ใช้คำนวณคลาดเคลื่อนไปสัก 20--30\% (ซึ่งเป็นเรื่องปกติของข้อมูลช่องโหว่ในโลกจริง)
อันดับความอันตรายที่ได้จะยังเชื่อถือได้หรือไม่ ข้อสองคือ \textbf{ยังไม่มีงานที่รวม
เครือข่ายภายในองค์กรกับคลาวด์เข้าเป็นกราฟเดียวกันแล้ววิเคราะห์จุดตัด (choke point)
อย่างเป็นระบบ} โดยใช้ทั้งวิธีเชิงโครงสร้าง (dominator tree) และเชิงความน่าจะเป็น
($-\log p$ + Dijkstra) เปรียบเทียบกันโดยตรง

\section{วัตถุประสงค์}\label{sec:intro-objectives}

\begin{enumerate}[leftmargin=1.6em]
\item ออกแบบโมเดลกราฟการโจมตีที่ใช้ ``สถานะของผู้โจมตี'' เป็น node คือคู่ของทรัพยากร
กับระดับสิทธิ์ (เช่น เครื่อง A ระดับ root) และครอบคลุม edge ที่ข้ามจากเครือข่ายภายใน
องค์กรไปคลาวด์อย่างชัดเจน
\item ทำวิธีให้ค่า $p(e)$ ที่อธิบายที่มาได้ทุก edge ทั้ง edge ที่มี CVE (ใช้ EPSS) และ edge
ที่เป็น misconfiguration (เทียบค่าจากความสัมพันธ์ CVSS--EPSS)
\item ใช้ dominator tree หาจุดตัดที่รับประกันบนกราฟที่มีทิศทาง แล้วเทียบกับผลจาก
weighted min-cut ดูว่าสองวิธีให้คำตอบตรงกันหรือไม่
\item วัดว่าอันดับ choke point เปลี่ยนแปลงเท่าไรเมื่อรบกวนค่าน้ำหนักและเมื่อข้อมูลกราฟ
ขาดหาย รวมถึงตอบว่าการใช้ EPSS ช่วยได้จริงกว่าการใช้ CVSS เฉย ๆ หรือไม่
\item สร้าง lab จริงทั้งสองฝั่งด้วย GNS3 + Nessus และ AWS + Terraform แล้วดึงข้อมูล
เข้า Neo4j ด้วย Cartography เพื่อยืนยันว่าโมเดลใช้กับระบบจริงได้
\end{enumerate}

\section{ขอบเขตของโครงงาน}\label{sec:intro-scope}

\subsection{อยู่ในขอบเขต}
\begin{itemize}[leftmargin=1.6em]
\item กราฟจำลองอย่างน้อย 200 กราฟสำหรับงานสถิติ บวกกราฟจริงจาก lab ทั้งฝั่ง network,
cloud และแบบรวมสองฝั่ง
\item การวิเคราะห์เชิงโครงสร้าง (dominator tree) และเชิงความน่าจะเป็น ($-\log p$) บนกราฟ
ชุดเดียวกัน
\item การทดสอบความทนทาน: รบกวนน้ำหนัก $\pm 10$--$50\%$, สุ่มลบ edge $5$--$20\%$ และ
เปรียบเทียบโมเดลน้ำหนัก 4 แบบ
\item ข้อสมมติที่ประกาศไว้ล่วงหน้า: ใช้ OR-semantics (ไม่รองรับ AND-node แบบ MulVAL),
สมมติว่าผู้โจมตีไม่เสียสิทธิ์ที่ได้มาแล้ว (monotonic) และสมมติว่า edge เป็นอิสระต่อกัน
(edge independence)
\end{itemize}

\subsection{นอกขอบเขต}
\begin{itemize}[leftmargin=1.6em]
\item การสั่งแก้ไขการตั้งค่าโดยอัตโนมัติ (auto-remediation)
\item การเขียนตัวเก็บข้อมูลขึ้นใหม่แทน Cartography
\item การตรวจจับแบบ real-time
\item การรองรับ AND-node เต็มรูปแบบ
\end{itemize}

\section{ประโยชน์ที่คาดว่าจะได้รับ}\label{sec:intro-benefits}

\begin{enumerate}[leftmargin=1.6em]
\item วิธีให้น้ำหนัก edge ที่อธิบายที่มาได้ทุก edge พร้อมเกณฑ์เทียบค่าที่คนอื่นทำซ้ำได้
\item ตัวเลขว่าน้ำหนักคลาดเคลื่อนได้เปอร์เซ็นต์เท่าไรก่อนอันดับ choke point จะเชื่อถือไม่ได้
(รายงานด้วย Kendall's $\tau$ และสัดส่วนการซ้อนทับของอันดับต้น ๆ)
\item อัตราที่ dominator tree กับ weighted min-cut ให้คำตอบไม่ตรงกัน ซึ่งเป็นข้อมูลที่
เครื่องมือเชิงพาณิชย์ในปัจจุบันไม่รายงาน
\item คำตอบว่าต้องแบ่ง segment เครือข่ายละเอียดแค่ไหนจึงจะเกิดจุดตัดที่รับประกันได้จริง
และสัดส่วนของเส้นทางอันตรายที่วิ่งผ่าน edge ข้ามโดเมน
\item ตัววิเคราะห์และตัวสร้างกราฟจำลองแบบ open source พร้อมชุดข้อมูลผลการทดลองและ
รายงานฉบับสมบูรณ์
\end{enumerate}
