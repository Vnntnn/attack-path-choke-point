\chapter{ทฤษฎีและงานที่เกี่ยวข้อง}

\section{กราฟการโจมตี (Attack Graph)}

แนวคิดการแทนระบบคอมพิวเตอร์เป็นกราฟที่ node คือสถานะของผู้โจมตีและ edge คือการ
กระทำหนึ่งครั้ง มีรากฐานจากงานของ Sheyner และคณะ~\cite{sheyner2002} ที่เสนอวิธีสร้าง
attack graph โดยอัตโนมัติจากโมเดลช่องโหว่ของระบบ พร้อมวิธีวิเคราะห์หาเส้นทางที่
ผู้โจมตีใช้โจมตีเป้าหมายได้ งานนี้วางรากฐานของ model checking สำหรับความมั่นคง
ปลอดภัย แต่ยังจำกัดอยู่ที่เครือข่ายขนาดเล็กเพราะต้นทุนการคำนวณสูง

Ou และคณะ~\cite{ou2005} เสนอ MulVAL ซึ่งแก้ปัญหาต้นทุนการคำนวณด้วยการใช้
Datalog เป็นภาษาอธิบายกฎการโจมตี และเพิ่มแนวคิด \textbf{AND-node} เข้าไปในกราฟ:
node บางตัวต้องการ predecessor \emph{ครบทุกตัว} จึงจะไปถึงได้ (ต่างจาก OR-node
ทั่วไปที่ต้องการเพียงตัวเดียว) เช่น การโจมตีที่ต้องอาศัยทั้งช่องโหว่ซอฟต์แวร์ \emph{และ}
การตั้งค่าไฟร์วอลล์ที่ผิดพร้อมกัน โครงงานนี้เลือกใช้ OR-semantics ล้วน (ไม่รองรับ
AND-node) ตามที่ประกาศไว้ในขอบเขต (หัวข้อ 1.4) เพื่อให้การวิเคราะห์ dominator tree
ตรงไปตรงมาและต้นทุนการคำนวณคาดเดาได้ แลกกับการไม่สามารถแทนเงื่อนไขที่ต้องการ
หลายอย่างพร้อมกันได้ (ข้อจำกัดในหัวข้อ 5.11)

\section{การเสริมความมั่นคงด้วยต้นทุนต่ำสุด}

Noel และคณะ~\cite{noel2003} เสนอวิธีหาชุดการเสริมความมั่นคง (hardening) ที่ต้นทุนต่ำ
ที่สุดบน exploit dependency graph โดยตั้งคำถามแบบเดียวกับโครงงานนี้ว่า node/edge
ใดบ้างที่ถ้าตัดออกแล้วทำให้ผู้โจมตีไปไม่ถึงเป้าหมาย งานนี้เป็นที่มาแนวคิดของการหา
\emph{min-cut} บน attack graph ซึ่งโครงงานนี้นำมาเทียบกับ dominator tree โดยตรง
(หัวข้อ 3.6 และ 5.2) ต่างจากงานของ Noel ตรงที่โครงงานนี้ใช้ weighted \emph{node}
min-cut ผ่านเทคนิค node-splitting แทน edge-cut และเปรียบเทียบกับจุดตัดเชิงโครงสร้าง
ที่ไม่อ่านน้ำหนักควบคู่กันไป

\section{Dominator Tree}

การหา node ที่อยู่บนทุกเส้นทางจาก root ไปยัง node หนึ่ง (dominator) เป็นปัญหาคลาสสิก
ของทฤษฎีกราฟที่มีทิศทาง อัลกอริทึมมาตรฐานที่ใช้ในโครงงานนี้ (ผ่าน
\texttt{networkx.immediate\_dominators}) อิงจากงานของ Lengauer และ
Tarjan~\cite{lengauer1979} ซึ่งคำนวณ dominator tree ทั้งต้นด้วยเวลาใกล้เชิงเส้น
เดิมทีอัลกอริทึมนี้ถูกออกแบบมาสำหรับการวิเคราะห์โปรแกรม (control-flow graph) เพื่อหา
จุดที่การไหลของโปรแกรมต้องผ่านเสมอ โครงงานนี้นำมาประยุกต์ใช้กับ attack graph แทน
โดยตีความ ``จุดที่โปรแกรมต้องผ่าน'' เป็น ``จุดที่ผู้โจมตีต้องผ่าน''

\section{CVSS และ EPSS}

Common Vulnerability Scoring System (CVSS)~\cite{cvss31} ให้คะแนนความรุนแรงของ
ช่องโหว่หนึ่งรายการจากคุณสมบัติของตัวช่องโหว่เอง (เช่น ต้องเข้าถึงจากเครือข่ายหรือ
เครื่องเดียวกัน, ต้องมีสิทธิ์ก่อนหรือไม่) แต่ไม่ได้บอกว่าช่องโหว่นั้นมีโอกาสถูกใช้โจมตีจริง
ในโลกมากน้อยเพียงใด Exploit Prediction Scoring System
(EPSS)~\cite{jacobs2019,epss} แก้ช่องว่างนี้ด้วยการฝึกโมเดลทำนายจากข้อมูลการโจมตี
จริงที่สังเกตได้ (telemetry) ให้คะแนนความน่าจะเป็นที่ CVE หนึ่งรายการจะถูกใช้โจมตีจริง
ภายในกรอบเวลาหนึ่ง สองคะแนนนี้วัดคนละสิ่งกัน: CVSS วัด ``รุนแรงแค่ไหนถ้าถูกใช้''
ส่วน EPSS วัด ``มีโอกาสถูกใช้ที่ไหนสักแห่งในโลกแค่ไหน'' ไม่ใช่ ``มีโอกาสสำเร็จเมื่อผู้โจมตี
ยืนอยู่ต้นทางแล้วแค่ไหน'' ความแตกต่างนี้เป็นเหตุผลที่โครงงานนี้ต้อง fit ความสัมพันธ์
ระหว่างสองคะแนนขึ้นมาเอง (หัวข้อ 3.2 และ 5.1) แทนที่จะใช้ตัวใดตัวหนึ่งแทนกันตรง ๆ
บน edge ที่เป็น misconfiguration ซึ่งไม่มี CVE ให้คะแนน EPSS โดยตรง

\section{เครื่องมือที่เกี่ยวข้อง}

เครื่องมือกลุ่ม Attack Path Management เชิงพาณิชย์ เช่น BloodHound (เน้น Active
Directory), Wiz (เน้นคลาวด์) และ XM Cyber ใช้แนวคิด attack graph ในระดับการใช้งาน
จริง แต่มุ่งที่ฝั่งใดฝั่งหนึ่ง (on-prem หรือ cloud) เป็นหลัก และไม่เปิดเผยที่มาของคะแนน
ความอันตรายที่ใช้จัดอันดับ โครงงานนี้ใช้ Cartography (เครื่องมือโอเพนซอร์สที่ดึงข้อมูล
โครงสร้างพื้นฐานคลาวด์เข้า Neo4j) เป็นตัวเก็บข้อมูลฝั่งคลาวด์ของ lab จริง (หัวข้อ 4.5)
โดยไม่เขียนตัวเก็บข้อมูลขึ้นใหม่ ตามที่ประกาศไว้ในขอบเขต

\section{ช่องว่างที่โครงงานนี้เติมเต็ม}

จากงานวิจัยและเครื่องมือข้างต้น โครงงานนี้ไม่ได้เสนอวิธีใหม่ในการสร้างหรือวิเคราะห์
attack graph แต่เติมช่องว่างสามจุดที่งานก่อนหน้าไม่ได้ตอบพร้อมกัน: (1) วิธีให้น้ำหนัก
edge ที่อธิบายที่มาได้ทุกเส้น แยกตามว่าเป็น CVE จริง (ใช้ EPSS~\cite{jacobs2019,epss})
หรือ misconfiguration (fit จาก CVSS~\cite{cvss31} โดยอ้างอิง
CWE~\cite{cwe}/CIS~\cite{cis} รายคลาส) (2) การเทียบ dominator
tree~\cite{lengauer1979} กับ weighted min-cut~\cite{noel2003} บนกราฟชุดเดียวกัน
โดยตรง แทนที่จะใช้วิธีใดวิธีหนึ่งเพียงอย่างเดียวตามที่งานก่อนหน้าทำ และ (3) การวัด
ความน่าเชื่อถือของอันดับจุดตัดอย่างเป็นระบบ (Jaccard@$k$, Kendall's $\tau$ เมื่อรบกวน
น้ำหนักและเมื่อข้อมูลขาดหาย) ซึ่งเป็นคำถามที่เครื่องมือเชิงพาณิชย์ไม่เคยตอบ
