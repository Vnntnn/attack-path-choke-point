\chapter{สิ่งที่ศึกษา}\label{ch:studied}

\section{ทฤษฎีและงานที่เกี่ยวข้อง}\label{sec:theory}
\subsection{กราฟการโจมตี (Attack Graph)}\label{sec:theory-attackgraph}

แนวคิดการแทนระบบคอมพิวเตอร์เป็นกราฟที่ node คือสถานะของผู้โจมตีและ edge คือการ
กระทำหนึ่งครั้ง มีรากฐานจากงานของ Sheyner และคณะ~\cite{sheyner2002} ที่เสนอวิธีสร้าง
attack graph โดยอัตโนมัติจากโมเดลช่องโหว่ของระบบ พร้อมวิธีวิเคราะห์หาเส้นทางที่
ผู้โจมตีใช้โจมตีเป้าหมายได้ งานนี้วางรากฐานของ model checking สำหรับความมั่นคง
ปลอดภัย แต่ยังจำกัดอยู่ที่เครือข่ายขนาดเล็กเพราะต้นทุนการคำนวณสูง

Ou และคณะ~\cite{ou2005} เสนอ MulVAL ซึ่งแก้ปัญหาต้นทุนการคำนวณด้วยการใช้
Datalog เป็นภาษาอธิบายกฎการโจมตี และเพิ่มแนวคิด \textbf{AND-node} เข้าไปในกราฟ:
node บางตัวต้องการ predecessor \emph{ครบทุกตัว} จึงจะไปถึงได้ (ต่างจาก OR-node
ทั่วไปที่ต้องการเพียงตัวเดียว) เช่น การโจมตีที่ต้องอาศัยทั้งช่องโหว่ซอฟต์แวร์ \emph{และ}
การตั้งค่าไฟร์วอลล์ที่ผิดพร้อมกัน โครงงานนี้เลือกใช้ OR-semantics ล้วน (ไม่รองรับ
AND-node) ตามที่ประกาศไว้ในขอบเขต (หัวข้อ~\ref{sec:intro-scope}) เพื่อให้การวิเคราะห์ dominator tree
ตรงไปตรงมาและต้นทุนการคำนวณคาดเดาได้ แลกกับการไม่สามารถแทนเงื่อนไขที่ต้องการ
หลายอย่างพร้อมกันได้ (ข้อจำกัดในหัวข้อ~\ref{sec:eval-limits})

\subsection{การเสริมความมั่นคงด้วยต้นทุนต่ำสุด}\label{sec:theory-hardening}

Noel และคณะ~\cite{noel2003} เสนอวิธีหาชุดการเสริมความมั่นคง (hardening) ที่ต้นทุนต่ำ
ที่สุดบน exploit dependency graph โดยตั้งคำถามแบบเดียวกับโครงงานนี้ว่า node/edge
ใดบ้างที่ถ้าตัดออกแล้วทำให้ผู้โจมตีไปไม่ถึงเป้าหมาย งานนี้เป็นที่มาแนวคิดของการหา
\emph{min-cut} บน attack graph ซึ่งโครงงานนี้นำมาเทียบกับ dominator tree โดยตรง
(หัวข้อ~\ref{sec:design-mincut} และ~\ref{sec:eval-cut}) ต่างจากงานของ Noel ตรงที่โครงงานนี้ใช้ weighted \emph{node}
min-cut ผ่านเทคนิค node-splitting แทน edge-cut และเปรียบเทียบกับจุดตัดเชิงโครงสร้าง
ที่ไม่อ่านน้ำหนักควบคู่กันไป

\subsection{Dominator Tree}\label{sec:theory-dominator}

การหา node ที่อยู่บนทุกเส้นทางจาก root ไปยัง node หนึ่ง (dominator) เป็นปัญหาคลาสสิก
ของทฤษฎีกราฟที่มีทิศทาง อัลกอริทึมมาตรฐานที่ใช้ในโครงงานนี้ (ผ่าน
\texttt{networkx.immediate\_dominators}) อิงจากงานของ Lengauer และ
Tarjan~\cite{lengauer1979} ซึ่งคำนวณ dominator tree ทั้งต้นด้วยเวลาใกล้เชิงเส้น
เดิมทีอัลกอริทึมนี้ถูกออกแบบมาสำหรับการวิเคราะห์โปรแกรม (control-flow graph) เพื่อหา
จุดที่การไหลของโปรแกรมต้องผ่านเสมอ โครงงานนี้นำมาประยุกต์ใช้กับ attack graph แทน
โดยตีความ ``จุดที่โปรแกรมต้องผ่าน'' เป็น ``จุดที่ผู้โจมตีต้องผ่าน''

\subsection{CVSS และ EPSS}\label{sec:theory-cvss-epss}

Common Vulnerability Scoring System (CVSS)~\cite{cvss31} ให้คะแนนความรุนแรงของ
ช่องโหว่หนึ่งรายการจากคุณสมบัติของตัวช่องโหว่เอง (เช่น ต้องเข้าถึงจากเครือข่ายหรือ
เครื่องเดียวกัน, ต้องมีสิทธิ์ก่อนหรือไม่) แต่ไม่ได้บอกว่าช่องโหว่นั้นมีโอกาสถูกใช้โจมตีจริง
ในโลกมากน้อยเพียงใด Exploit Prediction Scoring System
(EPSS)~\cite{jacobs2019,epss} แก้ช่องว่างนี้ด้วยการฝึกโมเดลทำนายจากข้อมูลการโจมตี
จริงที่สังเกตได้ (telemetry) ให้คะแนนความน่าจะเป็นที่ CVE หนึ่งรายการจะถูกใช้โจมตีจริง
ภายในกรอบเวลาหนึ่ง สองคะแนนนี้วัดคนละสิ่งกัน: CVSS วัด ``รุนแรงแค่ไหนถ้าถูกใช้''
ส่วน EPSS วัด ``มีโอกาสถูกใช้ที่ไหนสักแห่งในโลกแค่ไหน'' ไม่ใช่ ``มีโอกาสสำเร็จเมื่อผู้โจมตี
ยืนอยู่ต้นทางแล้วแค่ไหน'' ความแตกต่างนี้เป็นเหตุผลที่โครงงานนี้ต้อง fit ความสัมพันธ์
ระหว่างสองคะแนนขึ้นมาเอง (หัวข้อ~\ref{sec:design-pe} และ~\ref{sec:eval-pe}) แทนที่จะใช้ตัวใดตัวหนึ่งแทนกันตรง ๆ
บน edge ที่เป็น misconfiguration ซึ่งไม่มี CVE ให้คะแนน EPSS โดยตรง

\subsection{เครื่องมือที่เกี่ยวข้อง}\label{sec:theory-tools}

เครื่องมือกลุ่ม Attack Path Management เชิงพาณิชย์ เช่น BloodHound (เน้น Active
Directory), Wiz (เน้นคลาวด์) และ XM Cyber ใช้แนวคิด attack graph ในระดับการใช้งาน
จริง แต่มุ่งที่ฝั่งใดฝั่งหนึ่ง (on-prem หรือ cloud) เป็นหลัก และไม่เปิดเผยที่มาของคะแนน
ความอันตรายที่ใช้จัดอันดับ โครงงานนี้ใช้ Cartography (เครื่องมือโอเพนซอร์สที่ดึงข้อมูล
โครงสร้างพื้นฐานคลาวด์เข้า Neo4j) เป็นตัวเก็บข้อมูลฝั่งคลาวด์ของ lab จริง (หัวข้อ~\ref{sec:impl-lab})
โดยไม่เขียนตัวเก็บข้อมูลขึ้นใหม่ ตามที่ประกาศไว้ในขอบเขต

\subsection{ช่องว่างที่โครงงานนี้เติมเต็ม}\label{sec:theory-gap}

จากงานวิจัยและเครื่องมือข้างต้น โครงงานนี้ไม่ได้เสนอวิธีใหม่ในการสร้างหรือวิเคราะห์
attack graph แต่เติมช่องว่างสามจุดที่งานก่อนหน้าไม่ได้ตอบพร้อมกัน: (1) วิธีให้น้ำหนัก
edge ที่อธิบายที่มาได้ทุกเส้น แยกตามว่าเป็น CVE จริง (ใช้ EPSS~\cite{jacobs2019,epss})
หรือ misconfiguration (fit จาก CVSS~\cite{cvss31} โดยอ้างอิง
CWE~\cite{cwe}/CIS~\cite{cis} รายคลาส) (2) การเทียบ dominator
tree~\cite{lengauer1979} กับ weighted min-cut~\cite{noel2003} บนกราฟชุดเดียวกัน
โดยตรง แทนที่จะใช้วิธีใดวิธีหนึ่งเพียงอย่างเดียวตามที่งานก่อนหน้าทำ และ (3) การวัด
ความน่าเชื่อถือของอันดับจุดตัดอย่างเป็นระบบ (Jaccard@$k$, Kendall's $\tau$ เมื่อรบกวน
น้ำหนักและเมื่อข้อมูลขาดหาย) ซึ่งเป็นคำถามที่เครื่องมือเชิงพาณิชย์ไม่เคยตอบ

\section{การออกแบบระบบ}\label{sec:design}
\subsection{โมเดลกราฟการโจมตี}\label{sec:design-model}

node ของกราฟคือคู่ \texttt{(resource, privilege)} เช่น \texttt{(h001, root)} หมายถึง
``ผู้โจมตีถือสิทธิ์ root บนเครื่อง h001'' หรือ \texttt{(s3://bucket, read)} หมายถึง
``ผู้โจมตีอ่านข้อมูลจาก bucket นั้นได้'' การเข้ารหัสสิทธิ์ลงใน node เช่นนี้ (แทนที่จะแยก
``เครื่อง'' กับ ``สิทธิ์'' เป็นสองมิติ) ทำให้สถานะของผู้โจมตีสมบูรณ์ในตัวมันเอง: การประเมิน
ว่า edge หนึ่งใช้ได้หรือไม่ ดูที่ node ต้นทางเพียงอย่างเดียวก็พอ ไม่ต้องสืบว่าผู้โจมตีถือ
สิทธิ์อะไรมาก่อนหน้านั้นจากที่ไหน

edge หนึ่งเส้นแทนการกระทำหนึ่งครั้งของผู้โจมตี (หนึ่ง exploit หรือหนึ่งการเดินเครือข่าย)
แบ่งเป็นสามชนิดตามแหล่งที่มาของความน่าจะเป็น (หัวข้อ~\ref{sec:design-pe}) และมีคุณสมบัติ \texttt{domain}
กำกับทุกเส้นว่าอยู่ฝั่ง \texttt{onprem}, \texttt{cloud} หรือ \texttt{cross} (ข้ามจากฝั่งหนึ่งไปอีกฝั่ง)
edge ที่ \texttt{domain="cross"} คือใจกลางของวัตถุประสงค์ข้อ 1 ตัวตรวจสอบโครงสร้าง
(\texttt{validate\_structure}) บังคับว่ากราฟแบบ hybrid ต้องมี edge ข้ามโดเมนอย่างน้อย
หนึ่งเส้นเสมอ ไม่เช่นนั้นถือว่าไม่ใช่กราฟ hybrid จริง

โมเดลนี้อยู่ภายใต้สามสมมติฐานที่ประกาศไว้ตั้งแต่ขอบเขตของโครงงาน (หัวข้อ~\ref{sec:intro-scope}):
OR-semantics (node ไปถึงได้เมื่อมี predecessor \emph{อย่างน้อยหนึ่งตัว} ไปถึง ไม่ต้องมี
ครบทุกตัวแบบ AND-node ของ MulVAL), monotonic (ผู้โจมตีไม่เสียสิทธิ์ที่ได้มาแล้ว) และ
edge independence ($p(e)$ ของแต่ละ edge เป็นอิสระต่อกัน) ผลที่ตามมาคือ shortest path
ด้วย Dijkstra บน $w(e)=-\log p(e)$ ให้เพียง \textbf{ขอบเขตล่างของต้นทุนผู้โจมตี} ไม่ใช่
$P(\text{compromise})$ เพราะภายใต้ OR-semantics ยังมีเส้นทางอื่นที่ไปถึงเป้าหมายเดียวกัน
ได้อีก ซึ่งต้องรวมความน่าจะเป็นเข้าด้วยกัน (compound) ไม่ใช่เหลือเพียงเส้นทางเดียว

\subsection{ที่มาของความน่าจะเป็น $p(e)$}\label{sec:design-pe}

ทุก edge ต้องมี \texttt{p\_source} หนึ่งในสี่ค่า พร้อม \texttt{p\_input} ที่ระบุแหล่งที่มา
ตรงตัวของค่า $p$ นั้น ซึ่งเป็นข้อบังคับของวัตถุประสงค์ข้อ 2:

\begin{itemize}[leftmargin=1.6em]
\item \texttt{epss} -- edge ที่มี CVE จริง ใช้คะแนน EPSS ของ CVE นั้นตรง ๆ
\item \texttt{fitted} -- edge ที่เป็น misconfiguration (ไม่มี CVE) ใช้ค่าจากฟังก์ชันที่ fit
ไว้ระหว่างเวกเตอร์ CVSS กับ EPSS (หัวข้อ~\ref{sec:design-rubric} และ~\ref{sec:eval-pe})
\item \texttt{deterministic} -- edge เชิงโครงสร้าง/reachability ล้วน (security group
เปิด \texttt{0.0.0.0/0}, flat VLAN, VPC peering, forest trust, role assume) ให้ $p=1.0$
เสมอ เพราะ edge เหล่านี้ตัดสินว่า \emph{edge มีอยู่หรือไม่} ไม่ใช่ว่าถูกเจาะสำเร็จหรือไม่ -- การ
ใส่ $p<1$ ให้ edge ชนิดนี้จะเป็นการประเมินความเสี่ยงต่ำกว่าความเป็นจริง
\item \texttt{expert} -- ค่าสำรองที่ประกาศไว้ชัดเจน ใช้เมื่อ CVE ไม่มีคะแนน EPSS ในฐานข้อมูล
หรือ misconfiguration class ยังไม่ได้ fit (เช่นโมเดล \texttt{cvss}/\texttt{uniform}/\texttt{random}
ที่ใช้เปรียบเทียบในหัวข้อ~\ref{sec:design-experiments}) ไม่ใช่ค่าเริ่มต้นเงียบ ๆ
\end{itemize}

การแบ่งสามชนิด (ไม่ยุบเป็นสองหรือรวมเป็นหนึ่ง) เป็นการตัดสินใจที่ตั้งใจ: edge เชิงโครงสร้าง
กับ edge เชิง exploit มีความหมายต่างกันโดยสิ้นเชิง การผสมสองความหมายจะทำให้ตีความ
$w(e)=-\log p(e)$ ผิดเพี้ยน (ดูภัยต่อความตรงของผลข้อ~\ref{item:threat-pscale} ในหัวข้อ~\ref{sec:eval-threats})

\subsection{Rubric ของ misconfiguration}\label{sec:design-rubric}

edge ชนิด \texttt{fitted} ต้องมีเวกเตอร์ CVSS v3.1 กำกับก่อนจะแปลงเป็น $p(e)$ ได้
rubric (ภาคผนวก~\ref{app:rubric}) กำหนดเวกเตอร์ให้ misconfiguration ทั้งหมด 18 class โดยยึดกฎ
``ให้คะแนนเทียบ node ต้นทาง'' กล่าวคือ CVSS ปกติให้คะแนนจากมุมผู้โจมตีบนอินเทอร์เน็ต
ที่ยังไม่มีอะไรเลย แต่ที่นี่แต่ละเวกเตอร์อธิบาย edge เดียว $u \to v$ โดยผู้โจมตี\emph{อยู่ที่
สถานะ $u$ แล้ว} เช่น \texttt{aws-key-on-host} ให้ \texttt{AV:L/PR:L} ไม่ใช่ \texttt{AV:N/PR:N}
เพราะผู้โจมตีต้องมี shell บนเครื่องนั้นอยู่ก่อนจึงจะอ่านไฟล์ credential ได้

ทั้ง 18 class แบ่งตามว่า impact ทั้งสามด้าน (C/I/A) เป็น \texttt{N} ครบทุกตัวหรือไม่: ถ้าใช่
แปลว่า edge นั้นให้แค่ \emph{reachability} ไม่ใช่ exploit จึงจัดเป็น \texttt{deterministic}
(4 class) และไม่ป้อนเข้าฟังก์ชัน fit เลย เพราะ CVE ที่เผยแพร่จริงทุกตัวมี impact อย่างน้อย
หนึ่งด้านที่ไม่ใช่ \texttt{N} -- เวกเตอร์ all-N จึงอยู่นอกขอบเขตข้อมูลที่ fit เคยเห็น ถ้าไม่ใช่
all-N แปลว่าเป็น exploit/abuse ก้าวหนึ่งจริง จัดเป็น \texttt{fitted} (14 class) แต่ละแถว
อ้างอิง CWE และ/หรือ CIS Benchmark ที่ตรงกับคลาสนั้น เพื่อให้การกำหนดเวกเตอร์ตรวจสอบ
ย้อนกลับได้ ไม่ใช่ดุลพินิจที่ไม่มีการบันทึก

\subsection{ตัวสร้างกราฟจำลอง}\label{sec:design-gen}

ตัวสร้างกราฟ (\texttt{attackpath/gen.py}) รับพารามิเตอร์สี่ตัว: ขนาด $n \in \{50, 200, 800\}$
node, ความหนาแน่นของ edge ข้ามโดเมน (\texttt{low}/\texttt{med}/\texttt{high}), การแบ่งส่วน
เครือข่าย (\texttt{flat}/\texttt{3tier}/\texttt{micro}) และ seed กราฟแบ่งสัดส่วน node ประมาณ
60\% ฝั่ง on-prem และ 40\% ฝั่ง cloud host แต่ละเครื่องมีสอง node เสมอ (\texttt{user} และ
\texttt{root}) เชื่อมด้วย edge ชนิด \texttt{cve} จริง (สุ่มจาก pool CVE ที่มี vector และ EPSS
พร้อมกันในข้อมูลที่ดึงมา -- หัวข้อ~\ref{sec:impl-pipeline}) ส่วน edge เดินเครือข่ายระหว่างเครื่อง (lateral
movement) แบ่งสัดส่วนประมาณ 50\% \texttt{cve}, 30\% \texttt{misconfig}, 20\%
\texttt{deterministic} และ degree ของแต่ละเครื่องถูกกำหนดตามการแบ่งส่วน
(\texttt{micro}=1 $<$ \texttt{3tier}=2 $<$ \texttt{flat}=3) โดยการออกแบบ ไม่ใช่โดยบังเอิญ

edge ข้ามโดเมนสุ่มจากคลาส 5 ชนิดที่กำหนดไว้ล่วงหน้า (เช่น \texttt{aws-key-on-host},
\texttt{ssrf-imdsv1-token}) จำนวนที่สุ่มขึ้นกับความหนาแน่นที่ตั้งไว้และขนาดกราฟ หลังสร้าง
โครงสร้างหลักแล้ว ตัวซ่อมกราฟ (\texttt{\_repair}) จะเติม edge ที่ถูกต้องตามนโยบาย
(ไม่ใช่ edge สมมติ) เท่าที่จำเป็น เพื่อให้ทุกคู่ (entry, target) ไปถึงกันได้ -- การแบ่งส่วน
แบบ \texttt{micro} ที่เข้มงวดมักต้องซ่อมมากกว่าแบบอื่น ซึ่งเป็นที่มาของข้อสังเกตในหัวข้อ~\ref{sec:eval-cross}
ว่าสัดส่วน ``ต้องข้ามโดเมน'' ส่วนหนึ่งมาจากการซ่อมกราฟ ไม่ใช่โครงสร้างธรรมชาติ

จำนวน entry และ target ถูกล็อกไว้ตายตัวตามขนาดกราฟ ($n{=}50{\to}3$ entry/$2$ target,
$200{\to}5/3$, $800{\to}8/4$) เพื่อไม่ให้ต้นทุนการคำนวณ \texttt{pairwise\_dominators}
($O(|entries| \times |targets|)$) หลุดจากที่ควบคุมได้ แต่ละเซลล์ของตารางปัจจัย (ขนาด
$\times$ ความหนาแน่น $\times$ การแบ่งส่วน = 27 เซลล์) สร้างซ้ำ 8 ครั้ง (\texttt{rep})
รวมเป็น 216 โครงสร้าง (เกินขั้นต่ำ 200 กราฟตามข้อเสนอแม้นับเฉพาะโครงสร้าง ก่อนคูณด้วย
โมเดลน้ำหนัก) seed ของแต่ละโครงสร้างคำนวณจากตำแหน่งของเซลล์และ \texttt{rep} โดยตรง
ไม่ขึ้นกับว่าเรียกใช้กี่ขนาดหรือกี่ \texttt{rep} ในการรันครั้งนั้น ทำให้กราฟชุดย่อยใด ๆ ทำซ้ำได้
เหมือนเดิมเสมอ (ตรวจสอบจริงด้วยการรันข้าม \texttt{PYTHONHASHSEED} หลายค่า) และบันทึก
\texttt{cve\_pool\_size} กับ \texttt{epss\_snapshot} ลงกราฟทุกครั้ง เพื่อให้มองเห็นได้ว่า
การทำซ้ำอ้างอิงข้อมูล snapshot ชุดใด

\subsection{นิยามจุดตัด}\label{sec:design-chokepoint}

``จุดตัด'' (choke point) ในโครงงานนี้มีสามนิยามที่ให้เซตต่างกัน (รายละเอียดเชิงตัวเลขใน
หัวข้อ~\ref{sec:eval-cut-defs}): \textbf{global} คือ node ที่อยู่บนทุกเส้นทางของ\emph{ทุก}คู่ (entry, target),
\textbf{per-target} คือ node ที่อยู่บนทุกเส้นทางที่ไปถึง target หนึ่งตัวจาก entry ใดก็ได้ และ
\textbf{per-pair} คือ node ที่อยู่บนทุกเส้นทางของคู่หนึ่งคู่โดยเฉพาะ global คำนวณสองวิธี
ที่พิสูจน์ได้ว่าให้ผลเท่ากันเสมอ: วิธีแรกเติม super-source ไปทุก entry และ super-sink จาก
ทุก target แล้วใช้ dominator tree มาตรฐาน (Lengauer--Tarjan ผ่าน
\texttt{nx.immediate\_dominators}) วิธีที่สองคำนวณทีละคู่แล้วตัดฉันทามติ (intersect)
ความเท่ากันของสองวิธีนี้ใช้เป็น\emph{แบบทดสอบความถูกต้องของโค้ด} ไม่ใช่ผลการทดลอง
(การรายงาน ``อัตราความไม่ตรงกัน'' ระหว่างสองวิธีนี้เป็นการหลอกตัวเอง เพราะพิสูจน์แล้วว่า
เท่ากันเสมอ) คู่ที่ target ไปไม่ถึงเลยจะถูก\emph{ข้าม} ไม่นับเป็นเซตว่าง เพราะการนับเป็นเซต
ว่างจะทำให้ความเท่ากันข้างต้นพังทันที (เซตว่างตัดกับอะไรก็ได้เซตว่าง)

เพื่อให้จัดอันดับ node ได้ (ไม่ใช่แค่บอกว่าอยู่ในเซตหรือไม่) แต่ละ node จึงมีคะแนน
$\Delta(v) = \text{cost}(G{-}v) - \text{cost}(G)$ คือต้นทุนรวมของผู้โจมตีที่เพิ่มขึ้นเมื่อลบ $v$
ทิ้ง (ต้นทุนรวมของผู้โจมตีนี้คือผลรวมต้นทุนเส้นทางถูกสุดของทุกคู่ที่ยังไปถึงกัน) global
dominator set พิสูจน์ได้ว่าเท่ากับเซต $\{v : \Delta(v) = \infty\}$ พอดี (ตรวจด้วย brute force
ในหัวข้อ~\ref{sec:impl-repro}) จุดตัดเชิงโครงสร้างจึงไม่ใช่วิธีที่แยกจากชั้นความน่าจะเป็น แต่เป็นกรณีสุดขั้ว
ของมัน node กลุ่มนี้มีค่า $\Delta$ เท่ากันหมด (เพราะลบตัวใดก็ตัดทุกเส้นทางเหมือนกัน) จึง
จัดอันดับกันเองไม่ได้ และต้องรายงาน $n_{\inf} = |\{v : \Delta(v)=\infty\}|$ กำกับทุกครั้ง: ถ้า
$n_{\inf} \geq k$ การเลือก top-$k$ จากกลุ่มนี้เป็นการเลือกโดยพลการ ค่า Jaccard@$k$ ที่คำนวณ
ได้จึงไม่มีความหมาย ต้องรายงานสัดส่วนกราฟที่เข้าเงื่อนไขนี้คู่กับ Jaccard@$k$ เสมอ เช่นเดียวกับ
$n_{\text{tie\_at\_}k}$ ที่นับว่า node กี่ตัวเสมอกับ node อันดับที่ $k$ พอดี (ตัดสินด้วยเลข id แทน
เมื่อคะแนนเท่ากัน เพื่อให้อันดับทำซ้ำได้)

\subsection{Weighted Min-Cut}\label{sec:design-mincut}

การเปรียบเทียบ dominator กับ weighted min-cut (วัตถุประสงค์ข้อ 3) ต้องให้ทั้งสองคืนค่า
ในหน่วยเดียวกันคือ \emph{เซตของ node} ไม่ใช่ node เทียบกับ edge วิธีมาตรฐานคือ
node-splitting: แตก node $v$ เป็น $v_{\text{in}} \to v_{\text{out}}$ โดยวางน้ำหนักของ $v$ ไว้
บน edge ภายในเส้นนี้ ส่วน edge เดิมของกราฟให้ capacity เป็นอนันต์ เมื่อรัน min-cut
มาตรฐาน (\texttt{nx.minimum\_cut}) บนกราฟที่แตกแล้ว cut ที่ได้จะเลือกตัด edge ภายใน
เท่านั้น (ไม่มีทางถูกกว่าตัด edge เดิมที่ capacity อนันต์) จึงแปลงกลับเป็นเซต node ได้ตรง ๆ
entry และ target เองได้ capacity อนันต์เสมอ -- ``ป้องกัน'' ระบบด้วยการลบจุดเริ่มต้นหรือ
เป้าหมายทิ้งไม่ใช่แนวทางป้องกันที่สมเหตุสมผล

รายงานผล capacity สามแบบคู่กัน: \texttt{unit} (นับ 1 ต่อ node, เทียบหน่วยตรงกับ
dominator ได้โดยตรงเพราะ dominator ไม่อ่านน้ำหนักเลย), \texttt{prob} (ค่า $p$ สูงสุดของ
edge ขาเข้า, เป็นค่าตั้งต้น) และ \texttt{cost} ($-\log p$ ของ edge ขาเข้าที่ถูกที่สุด) capacity
แบบ \texttt{cost} เสื่อม (degenerate) บนกราฟที่มี edge เชิงโครงสร้าง: edge เหล่านั้นมี $p=1$
จึง $w=0$ ทำให้ node ที่เข้าถึงได้ฟรีมี capacity ศูนย์ และ min-cut ยุบไปเลือกเซต
capacity ศูนย์ที่เลือกโดยพลการ (วัดได้จริงในหัวข้อ~\ref{sec:eval-cut-agree}) เพราะเหตุนี้ \texttt{cost} จึงรายงาน
ไว้เป็นคอลัมน์ sensitivity เท่านั้น ไม่ใช่ค่าหลักของการเปรียบเทียบ

\subsection{ตัวชี้วัด}\label{sec:design-metrics}

ตัวชี้วัดหลักคือ \textbf{Jaccard@$k$} ($k=5,10$) ซึ่งเทียบสัดส่วนที่ node ติดอันดับ top-$k$
ก่อนและหลังการรบกวนทับซ้อนกัน Kendall's $\tau$ เป็นตัวรอง เพราะ $\tau$ บนทั้งกราฟถูก
กลบด้วย tie จำนวนมาก (node ส่วนใหญ่ที่ไม่อยู่บนเส้นทางถูกสุดเลยมีคะแนนเท่ากันหมดคือศูนย์)
ทั้งสองตัวคำนวณจากคะแนน $\Delta(v)$ เท่านั้น Jaccard@$k$ มีสองรูปแบบรายงานคู่กันเสมอ:
แบบปกติ (ตัด top-$k$ ตรง ๆ) และแบบที่นับ node ที่เสมอกับ node อันดับที่ $k$ เข้าไปด้วย
(\texttt{top\_k\_set}) เพราะโครงสร้างแบบโซ่ทำให้ node ติดกันหลายตัวมีคะแนนเท่ากันเป๊ะ
plain top-$k$ จะตัดกลุ่มนั้นตามเลข id ซึ่งให้ Jaccard สูงเกินจริงเมื่อ tie-break เหมือนกันทุกครั้ง

ตัวเลขทั้งหมดที่รายงานเป็นค่าเฉลี่ยคำนวณบน\emph{กราฟ} ไม่ใช่บนแถว เพราะแต่ละกราฟมี
การทำซ้ำ (\texttt{rep}) ของสัญญาณรบกวนหลายครั้งซึ่งไม่เป็นอิสระต่อกัน ช่วงความเชื่อมั่น 95\%
ของค่าเฉลี่ยคำนวณด้วย bootstrap แบบสุ่มเลือกกราฟซ้ำได้ (resample with replacement)
ไม่ใช่สุ่มเลือกแถว ส่วนสัดส่วนของกราฟที่มีคุณสมบัติหนึ่ง ๆ (เช่น ``มี global choke point'')
ใช้ช่วงความเชื่อมั่นแบบ Wilson เพราะจำนวนกราฟที่เข้าเงื่อนไขมักน้อย ทำให้สูตรปกติ
(normal approximation) ให้ช่วงที่ผิดสัดส่วนได้ง่าย
